# Самостоятельное развёртывание

Ниже общая схема для Linux с systemd. Выберите собственные пути, системного
пользователя и ограничения ресурсов. Конфигурация рабочего сервера исходного
проекта в открытую копию не включена.

1. Создайте отдельного системного пользователя без интерактивного входа.
2. Разместите код в каталоге релиза и создайте виртуальное окружение Python 3.11+.
3. Установите `requirements.txt`, выполните `python -m pytest -q`.
4. Передайте настройки из `.env.example` через файл окружения с ограниченными
   правами. SQLite разместите в отдельном записываемом каталоге пользователя службы.
5. В systemd укажите `WorkingDirectory` с кодом, `EnvironmentFile` с настройками,
   `ExecStart` с Python виртуального окружения и `main.py`, `User` с именем пользователя.
   Добавьте `Restart=on-failure`, `NoNewPrivileges=true`, `ProtectSystem=strict`
   и `ReadWritePaths` с выбранным каталогом данных.
6. Остановите другие экземпляры с тем же токеном, включите службу и проверьте
   `/start`, заметки, сборку, историю, сохранность после перезапуска.

Приложение использует polling: нужны исходящие соединения к Telegram и DeepSeek.
Входящий HTTP-сервер, домен и reverse proxy приложению не требуются.

Релизы держите раздельно. Перед переключением запускайте тесты и сохраняйте
предыдущий код для отката. При изменении схемы SQLite отдельно оцените совместимость
базы со старым релизом; переключение кода само по себе не откатывает данные.

Для резервной копии работающей SQLite используйте её backup API или команду
`.backup`, а не простое копирование файла. Сохраняйте используемый промпт, ограничьте
доступ к резервным копиям и проверяйте восстановление в отдельном каталоге.
