# MK-Video-Audit-public

Telegram-бот для подготовки видеоразбора карточки товара по текстовым заметкам.
Пользователь собирает наблюдения в черновик, а бот отправляет их в **DeepSeek API**
и возвращает сообщение продавцу, план скринкаста и короткое саммари.

Это очищенная открытая версия проекта. Она содержит код приложения, тесты
и демонстрационный промпт. Рабочий экспертный профиль, клиентские материалы,
базы данных, доступы, сведения об инфраструктуре и история приватного репозитория
в эту копию не включены. Демонстрационный промпт не проходил экспертную калибровку
исходного профиля.

## Возможности

- Доступ по списку Telegram ID (`ALLOWED_USER_IDS`).
- Несколько текстовых заметок на один разбор; SQLite сохраняет черновики и историю.
- Постоянное меню: новый разбор, сборка сценария, история, очистка черновика.
- После завершения следующая заметка начинает новый разбор. Дополнить прежний можно
  кнопкой под его результатом.
- Переключение двух моделей; готовый вариант на тех же заметках берётся из истории.
- Версии анализов с моделью, снимком заметок и версией промпта.
- Запрос уточнений одним сообщением, если данных недостаточно.
- Защита от одновременной сборки одного кейса и ограниченные повторы временных ошибок API.
- Раздельные сообщения с заголовками и текстами блоков для копирования с телефона.

Скриншоты, голос, OCR и загрузка карточек по ссылкам не поддерживаются. Подпись
к файлу сохраняется как текст, содержимое файла не анализируется. Ссылки остаются
частью заметок; бот не скачивает страницы.

## Данные и внешние сервисы

Анализ выполняется через [DeepSeek API](https://api.deepseek.com) с помощью
`AsyncOpenAI` из библиотеки `openai`. Текст заметок и системный промпт отправляются
в DeepSeek. Для работы нужны собственный API-ключ и доступ к выбранным моделям;
запросы оплачиваются по условиям провайдера. В `/start` есть уведомление об обработке
через DeepSeek API.

Заметки и результаты хранятся локально в SQLite. `DEBUG_REASONING=0` оставляйте
выключенным для обычной работы: отладочные рассуждения могут содержать фрагменты
входных данных. В стандартной конфигурации Python уровень DEBUG не выводится;
флаг используется при дополнительно включённом отладочном логировании.

## Запуск

Нужен Python 3.11+ и собственный Telegram-бот, созданный через @BotFather.
На один токен запускайте один экземпляр приложения.

```bash
python -m venv .venv
# Linux/macOS:
source .venv/bin/activate
# Windows PowerShell:
# .\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

Скопируйте `.env.example` в `.env` и заполните `BOT_TOKEN`, `DEEPSEEK_API_KEY`,
`ALLOWED_USER_IDS`, `MODEL_FAST`, `MODEL_DEEP`. На Windows используйте
`Copy-Item .env.example .env`, на Linux/macOS — `cp .env.example .env`.
Названия моделей выбирайте по доступности в своём аккаунте и документации DeepSeek.
Если модель не поддерживает `temperature`, оставьте `TEMPERATURE=` пустым.

```bash
python main.py
```

Откройте чат с ботом и отправьте `/start` с аккаунта из `ALLOWED_USER_IDS`.
Для локальных экспериментов используйте отдельный токен, если другой экземпляр
уже работает с вашим основным ботом.

## Настройки

| Переменная | Назначение |
| --- | --- |
| `BOT_TOKEN` | Токен Telegram-бота |
| `DEEPSEEK_API_KEY` | Ключ DeepSeek API |
| `ALLOWED_USER_IDS` | Telegram ID через запятую или пробел |
| `MODEL_FAST`, `MODEL_DEEP` | Два варианта модели для переключения |
| `DEEPSEEK_BASE_URL` | Адрес API, по умолчанию `https://api.deepseek.com` |
| `TEMPERATURE` | Температура или пустое значение, чтобы не передавать параметр |
| `MAX_TOKENS` | Лимит ответа; пример: 32000, включая рассуждения у соответствующих моделей |
| `REQUEST_TIMEOUT` | Таймаут запроса в секундах |
| `MAX_RETRIES` | Максимальное число попыток, включая первую |
| `DB_PATH` | Путь SQLite; в примере `./data/audit.db` |
| `PROMPT_PATH` | Файл системного промпта; относительный путь от каталога приложения |
| `DEBUG_REASONING` | Разрешение отладочного логирования рассуждений |

`.env` загружается при запуске, существующие переменные окружения имеют приоритет.
Токены, базы, заметки и логи не добавляйте в репозиторий.

## Промпт

В комплекте `prompts/demo_video_audit_v1.0.md`. Можно подключить собственный файл
через `PROMPT_PATH`. Версия берётся из имени файла (`v1.0`) и сохраняется с результатом.
После смены промпта перезапустите приложение.

При достаточных данных ответ должен иметь заголовки `БЛОК 1`, `БЛОК 2`, `БЛОК 3`
на отдельных строках. Без трёх блоков бот показывает ответ целиком и оставляет кейс
открытым. Экспертные выводы модели требуют проверки человеком.

## Тесты

```bash
python -m pytest -q
```

17 тестов используют подставной клиент без сетевых запросов: проверяют разбор ответа,
форматирование, SQLite, версии, изоляцию пользователей и двух последовательных
карточек, ошибки API и двойное нажатие. Эти тесты не доказывают качество выводов
реальной модели или устойчивость промпта к инъекциям.

```text
services/cases.py         SQLite, заметки и версии
services/deepseek_client.py  обращения к DeepSeek
services/formatter.py     блоки и форматирование Telegram
prompts/                  демонстрационный профиль
tests/                    автономные тесты
DEPLOY.md                 общая инструкция для Linux
```
